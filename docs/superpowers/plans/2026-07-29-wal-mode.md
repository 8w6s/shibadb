# WAL mode (deferred checkpoint) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make commit append to a multi-txn WAL + fsync only (2 fsync), deferring the data-file/superblock write to a threshold-triggered checkpoint, without weakening absolute durability.

**Architecture:** WAL becomes an append-only log of `[frame…][commit-record]` per txn. An in-memory `wal_index` (page_id → WAL offset) lets reads see committed-but-not-checkpointed pages. Checkpoint applies WAL→data, advances `superblock.checkpoint_lsn`, then truncates WAL. Recovery replays every committed txn with `txn_id > checkpoint_lsn`, stopping at the first torn/uncommitted tail txn. Single-writer + global mutex is unchanged in this sub-project.

**Tech Stack:** C11, CMake, ctest; existing `sdb_file_*`, `sdb_page_encode/decode`, `sdb_encrypted_page_*`, `sdb_crc32*`, `sdb_superblock_store_*`.

## Global Constraints

- C11; build must pass `-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Wstrict-prototypes -Wmissing-prototypes -Werror`.
- On-disk **data page format unchanged**; only WAL format + commit/checkpoint/read logic change.
- Public API + observable behavior **unchanged** (all existing ctest 38/38 must keep passing).
- Encrypted-by-default unchanged; WAL frames hold encrypted pages when encryption is on.
- Absolute durability: a committed txn survives power loss at any point; a torn txn vanishes wholly; DB never corrupts.
- Test-only hooks guarded by `#if SDB_TESTING`.
- Work on branch `feat/wal-mode`; do NOT merge to `main` until every merge-gate task passes.

### Task 5: Checkpoint

**Files:** Modify `src/pager.c`, `src/wal.c`; Test: `tests/test_wal_mode.c`.

**Interfaces:**
- Consumes: `wal_index` (Task 2), superblock store.
- Produces (static in pager): `static sdb_status sdb_pager_checkpoint(sdb_pager *pager);`
  - Applies every page in `wal_index` (newest offset) to the data file, `fsync(data)`, sets `superblock.checkpoint_lsn = pager->current_lsn` (+ `next_page_id`/`freelist`), writes+fsyncs superblock, truncates WAL to `SDB_WAL_HEADER_SIZE` (re-writes header; no fsync of truncate — checkpoint_lsn dominance), clears `wal_index`, resets `wal_tail`.
